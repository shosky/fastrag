# 成员管理 — 设计文档

## 1. 功能概述

**目的：** 管理应用的协作者，分配不同角色（管理员/编辑/查看者），实现应用级别的权限控制。

**当前状态：** 编辑器内联 mock 实现（纯前端增删改查，无 API 调用）。

**改造目标：** 新建 `MemberConfig.vue` 组件。后端当前无应用级 ACL API，需对接 IAM 模块的 `/api/personnel` 进行人员查询；应用级别的角色绑定需要新增后端 API 或使用前端本地管理（mock 接口）。

## 5. 实现要点

### 5.1 后端 API 缺失应对方案

由于后端尚无应用成员 API，采用**渐进式实现策略**：

- **阶段一（当前实现）**：成员数据存储在 `AppConfig.advancedOptions` JSON 中（与 VM 配置类似），前端做完整 CRUD，后端仅持久化 JSON
- **阶段二（后续迭代）**：后端新增 `app_member` 表 + API 端点，前端切换到真实 API

### 5.2 边界条件
- 成员名或账号为空 → 阻止保存，提示"请填写完整信息"
- 搜索无结果 → 显示空状态
- 删除最后一位管理员 → 提示"至少保留一位管理员"

### 5.3 角色权限说明

| 角色 | 权限范围 |
|------|----------|
| 管理员 | 全部操作：编辑配置、发布应用、管理成员 |
| 编辑 | 编辑配置（不含成员管理、发布操作） |
| 查看者 | 只读查看配置，无编辑权限 |

### 5.4 错误处理
- 保存失败 → 恢复原状态 + 错误提示
- 删除时二次确认 → 使用 `ElMessageBox.confirm`

### 5.5 备注
- 成员管理是应用层权限，区别于系统角色（IAM 模块）
- 应用创建者默认为管理员，不可移除
- 状态"禁用"表示成员暂不可访问此应用
