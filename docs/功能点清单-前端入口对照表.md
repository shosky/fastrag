## 附 H：演示操作要点（实测得到的真实接口契约）

以下均为实测确认的契约细节，按此操作可保证「有数据、有结果、不报错」：

| 场景 | 要点 |
|---|---|
| 启动顺序 | MySQL(fastrag2) → Redis → AI 网关(:11434) → 后端(:8080) → 前端(:3000)。AI 网关不可用时向量检索自动降级为词法模式（`source=keyword`），模型调用/测试/语义判断会失败 |
| 检索结果要求 | 知识库必须先有「已解析文件分块」（`kb_chunk`）或 FAQ 问答对；只建知识条目（`kb_knowledge`）不会进检索主链路 |
| 检索权限控制 | 以 ACL（Redis `kb:acl:{kbId}:{userId}` + `kb_acl` 表）为准；`kb.permission=public` 只是元数据，普通用户仍需授权行。演示「被拒」用 `demo` 账号访问未授权库 |
| 检索偏好 | `userId` 存登录**用户名**（admin）；前端「我的」筛选（`mine=true`）按用户名匹配 |
| 表格内容 | 行内容体为 `{"content":{"<colKey>":值}}`；列定义返回 `colKey`，需先取列再建行 |
| 知识库导入 | `POST /api/kb/import` 直接提交 `GET /api/kb/{id}/export` 返回的整个信封（`{version,type,exportedAt,knowledgeBase,files}`），不要自行拼 `kb/knowledge` 字段 |
| FAQ 问答对 | 字段名：`faqType`(common/uncommon)、`keywords`(逗号串)、`effectiveStart/End`、`effectiveScope`、`relatedKnowledgeIds`(JSON 字符串)；创建接口**不返回 id**（需从列表取） |
| 用户反馈 | 字段名：`feedback`(like/dislike)、`comment`、`category`、`score`(1-5)、`status`、`reply`；创建接口同样不返回 id |
| 语义定制 | 契约是 `intentPatterns:[{intent,patterns:[关键词],threshold}]` + `customSynonyms`；试判断按「关键词包含」匹配，问句需包含模式词 |
| 对话流配置 | 契约是 `{workflowIds:[...]}`，保存后 GET 回显；`kbIds/opening` 不持久化 |
| 查询规则 | 替换/扩写内容字段为 `replacement`（后端映射到 `rule_type` 对应的 `action`）；扩写多个词用空格分隔；`expansions` 字段后端不识别 |
| 模型阈值 | `PUT /api/models/{id}/threshold` 传 `{threshold:{...}}`；「删除」= 传空对象（MyBatis-Plus 跳过 null，故清空需传 `{}`） |
| 知识更新删除 | 仅 `pending` 状态可删除（`applied/rolled_back` 受保护，属业务约束） |
| 全部入库 | `POST /api/kb/{kbId}/qa-pairs/confirm-all` 将本库全部 `draft` 问答对置为已入库，返回 `{count}` |
| 监听执行情况 | `POST /listeners/dispatch` 只做分发不落日志；日志/统计/趋势读 `kb_listener_log`（演示库已补 12 条） |
| 手动更新知识库 | 应用需先绑定知识库（`POST /api/apps/{appId}/knowledge-bases`），否则返回 `status=no_kbs` |
| 节点扩展配置 | `PUT/GET/DELETE /api/workflows/{id}/nodes/{nodeKey}/{dimension}`，dimension 取值：`delays`/`resources`/`permissions`/`log-level`/`data-policies`/`backups`；返回 `value` 即当前配置 |
| JSON 串字段 | 凡后端实体里是 `String tags/config/suggestions/channels/preferTags/valuesJson/turns/outline/mediaIds` 的，均按**JSON 字符串**传（如 `"[\"a\"]"` 或 `"a,b"`，后者已兼容） |
