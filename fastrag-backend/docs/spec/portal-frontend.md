# 首页门户 — Frontend Spec

## 范围 {#scope}

本规格覆盖 FastRAG 前端新增的**首页门户**层（CONTEXT.md「首页门户」条目）。门户是一个独立于现有 AppLayout 平台壳的全宽布局，承载三个页面：门户首页（/portal）、操作手册（/portal/manual）、产品动态（/portal/changelog）。现有**平台**（CONTEXT.md「平台」条目，AppLayout + 侧边栏 + 全部功能）通过登录或门户按钮进入（**登录即进入平台**），平台内部结构零改动。

**2026-11-03 门户首页 Yuxi 式重构**（CONTEXT.md「门户首页重构决策快照」决策 1-26）：PAGE-001 信息架构按 [Yuxi 官网首页](https://xerrors.github.io/Yuxi/)的分区逻辑重排——「知识引擎 + 应用与智能体」双支柱行式呈现替代单一核心能力卡堆、「工作原理」三步扩四步、新增技术栈标签区、hero 升为四层文案；`views/portal/index.vue` 整页重写，顺带消除三处既有缺陷（重复「核心能力」分区、资源区 `resources` 未定义整区不渲染、`@keyframes rise-in` 重复定义）。门户壳（PortalLayout/PortalTopNav）、操作手册页、产品动态页零改动。

同时覆盖：门户三页公开访问（游客可浏览，游客态提供「登录」入口，登录成功落在平台内而非门户）；入口流跳转迁移（登录成功与已登录访问 /login 落 /home，`/` 与 404 兜底落 /portal）；平台侧边栏 logo 回门户；平台内 4 处「首页」显示文字改「主页」；document.title 后缀统一 FastRAG；操作手册素材结构化（manual.md 规范化并入前端仓库、产品名统一 FastRAG）。

显式排除：平台既有 60 条路由的功能、路径与权限结构改动；产品动态的后端接口与管理端维护（一期为前端静态数据）；门户菜单的角色权限配置；新增图片素材与插画（重写仅复用 public/portal 既有真实截图，不新拍截图、不绘制 SVG 插画）；深青色板与第三方 logo 墙（保持平台蓝白底、纯文字 pill）；模型供应商 icon 墙与 docker compose 快速开始代码块（开发者向重资产，不上）。

## 用户任务 {#user-tasks}

- **TASK-001** — 用户登录后进入平台。入口：登录页登录成功（login/index.vue 两处），登录成功落在平台 /home（登录即进入平台，不落门户）。权限：无菜单权限门禁。成功结果：落地平台 /home。失败恢复：登录失败停留登录页（既有流程）。
- **TASK-002** — 用户从门户进入现有平台。入口（2026-11-03 重构后收敛四类）：hero 主按钮、CTA 主按钮、顶导航按钮（三者同规则：游客「立即开始」→ /login，已登录「进入平台」→ /home）；业务场景卡整卡点击（跳 /home，游客由守卫重定向 /login）。权限：进入平台需要登录（游客由守卫重定向 /login）；平台内功能仍受现有权限体系约束。成功结果：跳转平台 /home。失败恢复：平台内权限不足走既有 /403 流程，门户侧无额外处理。
- **TASK-003** — 用户阅读操作手册。入口：顶导航「操作手册」、首页资源区「操作手册」卡、hero 次按钮「查看操作手册」。权限：公开，游客可浏览。成功结果：/portal/manual 渲染结构化手册全文，可通过两级目录按章/节导航。失败恢复：渲染异常时回退显示 Markdown 原文（STATE-001），不白屏。
- **TASK-004** — 用户查看产品动态。入口：顶导航「产品动态」、首页资源区「产品动态」卡。权限：公开，游客可浏览。成功结果：/portal/changelog 按版本倒序看到更新时间线。失败恢复：数据为空显示空态提示（STATE-002）。
- **TASK-005** — 已登录用户从平台返回门户。入口：平台侧边栏 logo 点击。权限：需已登录（游客不经过平台）。成功结果：跳转 /portal。失败恢复：无特殊处理。

## 页面与路由 {#pages-routes}

- **PAGE-001** — 首页门户，路由 `/portal`（PortalLayout 子路由，`/` 的 redirect 目标），公开访问。
  - 入口：404 兜底、平台侧边栏 logo（TASK-005）、顶导航「首页」、游客直访、已登录用户经侧边栏 logo 回访（登录成功落在平台，不落门户）。
  - 退出路径：顶导航其余两个菜单。
- **PAGE-002** — 操作手册，路由 `/portal/manual`，公开访问。入口：顶导航、首页资源卡、hero 次按钮（TASK-003）。返回路径：顶导航「首页」或 logo。
- **PAGE-003** — 产品动态，路由 `/portal/changelog`，公开访问。入口：顶导航、首页资源卡（TASK-004）。返回路径：顶导航「首页」或 logo。

路由归属与不变量：

- 三页同挂顶层 `/portal` 路由族，共用 PortalLayout 壳（全宽、顶部主导航、无侧边栏），与 AppLayout 平级并存、互不嵌套。
- `/` 改为 redirect `/portal`；404 兜底（catch-all）改为 redirect `/portal`；登录成功两处与守卫的「已登录访问 /login」改跳 `/home`（登录即进入平台）。
- 平台既有 60 条路由的 path、name、component 映射零变化；平台内导航 6 处（侧边栏首项、3 处面包屑、/403 返回、权限管理页路径下拉）继续指向平台 /home。
- 门户路由不在 MENU_PERMISSION_MAP 与 menu-perm-tree.ts 注册（守卫对未登记路径放行），角色权限配置页不出现门户节点。

## 状态矩阵 {#state-matrix}

- **STATE-001** — 手册渲染回退态（PAGE-002）。触发：Markdown 解析抛异常。可见反馈：内容区回退显示 Markdown 原文，页面不白屏、无报错弹窗。恢复：无用户侧恢复动作（素材随构建打包，异常属构建期缺陷）。
- **STATE-002** — 产品动态空态（PAGE-003；首页资源卡徽标随之隐藏）。触发：changelog 数组为空。可见反馈：时间线位置显示空态提示；首页「产品动态」卡不显示版本徽标。恢复：由维护者补充种子数据（非空列为验收项）。

| 页面 | initial / loading | empty | success | error / retry |
|---|---|---|---|---|
| PAGE-001 | 内容直出，无 loading 态（零异步数据） | 页面本身无空态，仅徽标受 STATE-002 派生影响 | 全部静态区块渲染 | 不适用（零后端接口） |
| PAGE-002 | 内容直出，无 loading 态 | 不适用（素材随构建打包，非空为验收项） | 全文渲染 + 目录滚动联动 | STATE-001 回退原文；无 retry |
| PAGE-003 | 内容直出，无 loading 态 | STATE-002 | 时间线渲染 | 不适用（零后端接口） |

不适用项声明：disabled / offline 状态对三个页面均不适用——门户一期无后端依赖、无可禁用操作。

## 响应式与可达性 {#responsive-accessibility}

响应式（统一 768px / 1024px 两档，跟随全仓主流断点惯例）：

- 视口 ≤1024px：hero 竖排（截图居下、文案居中）、hero 按钮允许换行；业务场景卡单列；为什么选卡 2×2；四步卡纵向；手册目录栏折叠为顶部下拉。
- 视口 ≤768px：为什么选卡与资源卡单列；技术栈 pill 允许换行；分区纵向留白收紧；产品动态时间线内边距收紧；顶导航菜单横向滚动，不引入汉堡菜单（内部系统，桌面优先）。

可达性（仅约束门户新代码，不回溯改造平台存量）：

- 顶导航菜单与全部按钮使用语义化可聚焦元素（router-link / button），可 Tab 到达、Enter 触发；禁止裸 div+click 交互。
- 双支柱子能力行、pill、技术栈标签为非交互元素——不参与 Tab 焦点序、不出现 pointer 光标、不伪装交互反馈（无 hover 位移）；业务场景卡与资源卡等可点击整卡继续用可聚焦语义元素实现。
- 焦点顺序 = DOM 顺序（左→右、上→下）。
- 明示不做：skip-link、ARIA 地标增强（与平台现状水准一致）。
- 动效可达性：首页入场/滚动渐显/悬浮等动效在 `prefers-reduced-motion: reduce` 下全部禁用，直接呈现最终态。
