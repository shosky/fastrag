# 应用对话 Widget（widget）— 需求规格

> 2026-10-31 由 idd-spec 依据 grill 裁决记录（根 CONTEXT.md「Widget 特性决策快照」#1-34，2026-10-30/31 六批裁决 + 批次 7 授权代裁）编写。
> 事实基线：前后端零存量 Widget 代码（纯绿地）；引擎已有「工具结构化结果直达前端」通道与前端「工具名 → 专用渲染器」路由先例——卡片协议在该既有通道上落地，不新增对话流事件面。
> 前端页面、状态矩阵与交互细节见 [widget-frontend.md](./widget-frontend.md)；本档只约束业务行为与可观测结果。

## 范围 {#scope}

Widget 是嵌入应用对话窗口的可交互自定义展示卡片：用户在 Widget 开发工作台以「模板 + 数据结构 + 默认值」三件套定义卡片资产，应用经绑定引用资产；对话中智能体按清单调用 render_widget 工具输出结构化数据，前端以 emit 时刻的快照渲染卡片；用户在卡片上的操作作为回传推进后续对话。本档覆盖四块能力：①资产管理（三件套 CRUD、三档结构校验、属主隔离、保存即生效）；②官方模板库（启动播种、只读、复制）；③应用绑定（第六类绑定、候选口径、数量上限、启用开关）；④对话协议（清单注入、render_widget 校验与快照、体积护栏、历史快照回显、操作回传）。消费面为凡挂载应用的对话（应用调试对话与会话中心挂应用的会话共用同一执行链）；纯直聊与工作流通道无 Widget。

## 排除范围 {#out-of-scope}

- **可视化拖拽编辑器 / 自然语言生成 Widget / Widget 文件导入导出**：一期仅手写 JSON 三件套，创建方式四选一仅落地「代码创建」与「官方模板复制」。〔快照 #2〕
- **工作流通道渲染**：工作流执行引擎为占位实现，无真实输出面；Widget 不接入。〔快照 #3〕
- **分享治理**：部门/全员三级可见性不做，v1 属主隔离；需要时照技能分享链立项。〔快照 #6〕
- **版本与发布流**：无资产版本、无发布审批，保存即生效（已知代价登记于约束节）。〔快照 #7〕
- **专用 Widget 流事件**：不新增对话流事件类型，卡片数据复用既有工具结果结构化通道；事件语义膨胀时再立项升级。〔快照 #11〕
- **模板表达式与条件语法**：模板不含 v-if 类分支语法，条件差异由智能体更换模板或数据表达。〔快照 #16〕
- **一期 19 组件之外的组件**：Box/Spacer/Label/Video/Audio/Countdown/Textarea/DatePicker/ImageSelect/Transition/Chart 后置，白名单与渲染注册表预留扩展位，但本期不实现渲染。〔快照 #15〕
- **交互窗口的后端状态机**：卡片可交互窗口由前端按消息序判定，后端不设失效表、不校验卡片操作时效。〔快照 #14〕
- **前端页面结构、元素清单与状态矩阵**：归 [widget-frontend.md](./widget-frontend.md)。

## 功能需求 {#requirements}

### 4.1 资产管理

Widget 资产是平台内被应用引用的一等资源：三件套（模板、数据结构、默认值）定义卡片的形态与数据契约，属主隔离决定可见性，保存即生效决定运行时读取口径。校验是本域第一道闸门——坏模板必须在保存时被拦下，而不是流到对话运行时才失败。

- **REQ-WG-A01**：系统应提供 Widget 资产的创建、查询、修改与删除；每个资产由名称、描述、图标与模板、数据结构、默认值三件套组成，模板为组件树、数据结构为模板变量的类型与格式声明、默认值为变量的占位数据。〔快照 #5〕
- **REQ-WG-A02**：当资产被创建或修改时，系统应执行三档结构校验——三件套各自为合法 JSON；模板中组件名均在组件白名单内且必填属性齐全；数据结构声明的变量与模板引用一致、默认值可按数据结构反序列化——任一档失败即拒绝保存，并以业务错误返回逐项行级错误信息。〔快照 #9〕
- **REQ-WG-A03**：在属主隔离下，系统应按创建者过滤资产列表（管理员可见全部），非属主读取或写入他人资产应被拒绝并以业务错误提示。〔快照 #6/#33〕
- **REQ-WG-A04**：资产保存成功后，系统应立即以新内容服务后续对话，不设版本与发布流转；已发出消息的卡片展示不受其后的资产修改影响（按消息内嵌快照渲染）。〔快照 #7/#12〕
- **REQ-WG-A05**：当删除被任一应用绑定的资产时，系统应拒绝删除并以业务错误提示先解除绑定；未被绑定的资产删除成功后，其后对话不再注入该资产。〔快照 #23〕
- **REQ-WG-A06**：系统应保证保存校验接受的组件名集合与前端渲染器可渲染的组件名集合一致：两端各持一份白名单常量，并由自动化测试守护一致（后端多出前端不认识的组件、或反之，测试必须失败）。〔快照 #9/#17〕

### 4.2 官方模板库

官方模板库是平台的 Widget 最佳实践入口：只读示例降低创建门槛，复制语义保证内置资产不被用户改坏。播种走启动幂等通道，与内置技能、内置 MCP 同型。

- **REQ-WG-B01**：系统应预置官方 Widget 模板集，于服务启动时自动播种入库：仅当对应内置记录不存在时插入，已存在的记录不覆盖用户可见状态之外的任何内容。〔快照 #8〕
- **REQ-WG-B02**：在官方模板行（内置标识）状态下，系统应拒绝修改与删除，仅提供查看与复制入口。〔快照 #8〕
- **REQ-WG-B03**：当用户复制一个官方模板时，系统应生成一条新的独立 Widget 资产——拷贝三件套、创建者为当前用户、不带内置标识——复制件可编辑、可绑定应用。〔快照 #8〕
- **REQ-WG-B04**：官方模板行不应出现在应用绑定候选集合中。〔快照 #8/#26〕

### 4.3 应用绑定

绑定是 Widget 进入对话的唯一通道：应用配置者从自建资产中挑选并启用，对话运行时按绑定装配。语义对齐既有五类绑定（知识库/工具/技能/MCP/数据库）的表形态、端点动词与权限要求。

- **REQ-WG-C01**：系统应支持应用与 Widget 资产的多对多绑定，每条绑定带启用开关；禁用的绑定在清单注入与卡片渲染两条链路上均不生效，等同未绑定。〔快照 #25/#26〕
- **REQ-WG-C02**：绑定候选集合应仅为当前用户的自建资产（管理员另加全员自建资产）；官方模板与无权访问的他人资产不可作为候选。〔快照 #26〕
- **REQ-WG-C03**：当单个应用的启用与禁用绑定总数达到上限（10）时，系统应拒绝继续添加并以业务错误提示上限。〔快照 #26〕
- **REQ-WG-C04**：绑定的新增、修改与删除应要求应用编辑权限，与既有五类绑定同口径。〔快照 #25/#33〕

### 4.4 对话触发与卡片数据

对话协议的核心是「清单注入 + 工具触发 + 快照传输」：绑定非空时把资产契约注入上下文，智能体经 render_widget 工具产出结构化数据，服务端校验后以定格快照经既有结构化通道送达前端并随消息落库。任何校验失败走工具错误文本回灌，由模型自纠，不中断对话。

- **REQ-WG-D01**：当本轮对话挂载的应用存在至少一条启用绑定时，系统应把绑定 Widget 的清单（标识、名称、用途、数据结构、默认值示例）注入对话上下文，并使智能体可调用 render_widget 工具；无启用绑定（含纯直聊）时不注入、不注册工具，对话行为与无本特性一致。〔快照 #10/#28〕
- **REQ-WG-D02**：当智能体调用 render_widget 时，系统应先校验调用指向的资产标识属于本次对话的绑定集合（集合外拒绝，防提示注入诱导渲染任意卡片），再加载资产并按其数据结构校验提交的数据。〔快照 #10/#33〕
- **REQ-WG-D03**：当校验通过时，系统应生成卡片渲染快照——含资产标识、卡片替换键、名称、模板与本次数据，快照在生成时刻定格——并随本轮工具结果返回前端。〔快照 #10/#12〕
- **REQ-WG-D04**：如果资产标识越界或数据校验失败，系统应以错误文本回灌智能体且不中断对话，由模型修正后重试。〔快照 #10/#33〕
- **REQ-WG-D05**：系统应对卡片数据施加体积护栏：提交数据序列化后超过 32KB 按校验失败路径处理；Widget 清单注入文本沿用上下文注入截断口径（5000 字符，超限按序截断并告警）。〔快照 #32〕
- **REQ-WG-D06**：当含卡片快照的助手消息落库时，快照应随消息持久化，使历史回看按快照原样渲染卡片，不依赖资产当前内容；同一卡片替换键的后续快照到达时，前端以新快照替换同键旧卡（过程反馈的进度推进）。〔快照 #12〕
- **REQ-WG-D07**：卡片数据应经既有工具结果结构化通道传输，不新增对话流事件类型；含卡片的消息与不含卡片的消息在事件词汇上无差别。〔快照 #11〕

### 4.5 操作回传

回传是卡片交互闭环的另一半：用户在卡片上的选择与输入转化为结构化负载，作为新一轮对话的输入推进流程。回传不是独立动作端点，而是对话消息通道上的一次携带负载的推进——停止、事件、错误语义全部复用对话流既有行为。

- **REQ-WG-E01**：当用户在可交互卡片上完成输入并提交时，前端应把回传负载（资产标识、卡片替换键、动作、表单数据）随对话消息发送，系统应将其推进为一轮新的对话执行（回传即后续任务输入）。〔快照 #13〕
- **REQ-WG-E02**：当回传发生时，系统应合成一条可见的用户消息（人类可读的文本摘要）落库展示，并把回传结构化负载以标注块注入本轮引擎上下文供模型消费。〔快照 #13〕
- **REQ-WG-E03**：当回传负载超过 16KB 时，系统应拒绝推进并返回业务错误。〔快照 #32〕
- **REQ-WG-E04**：回传应沿用所属对话通道的既有鉴权（应用对话通道要求应用使用权限、会话通道要求登录），不新增独立鉴权面。〔快照 #33〕

## 约束 {#constraints}

- **零新事件面**：卡片数据与快照走既有工具结果结构化通道，持久化复用消息的工具记录列，不新增流事件类型、不新增消息级卡片列。〔快照 #11/#12〕
- **保存即生效（代价已接受）**：修改资产即时影响绑定应用的后续对话；历史消息按快照稳定，不受影响。〔快照 #7〕
- **交互窗口纯前端**：可交互窗口由前端按消息序判定（仅最新一条助手消息可交互），后端零状态机、零失效表。〔快照 #14〕
- **DDL 双处同步**：资产表与绑定表的 DDL 必须在 SchemaInitializer 幂等增补与 schema.sql 全量脚本双处一致并列入验收（历史漂移教训：agent 表缺失、idx_content_fulltext 单侧）。〔快照 #5/#25〕
- **工具执行无副作用**：render_widget 执行仅为校验与快照透传，不产生沙箱、外部系统或数据写入副作用。〔快照 #10〕
- **错误口径**：资产校验、删除保护、绑定上限、回传超限等失败一律业务错误（HTTP 200 + body.code）行级返回，前端可定位到具体条目。〔快照 #9〕
- **越权防线 fail-closed**：运行时资产标识必须落在本次绑定集合内（REQ-WG-D02），配置面把关候选集合（REQ-WG-C02），两层共同封堵提示注入路径。〔快照 #33〕
- **可达性与安全基线在前端档**：消毒（禁 v-html、Markdown 单源消毒、图片地址协议白名单）与可达性约束见 [widget-frontend.md](./widget-frontend.md)。

## 验收清单 {#acceptance}

- [ ] 资产创建/查询/修改/删除可用，资产含名称、描述、图标与三件套（REQ-WG-A01）
- [ ] 三档校验逐档可触发：坏 JSON 拒、白名单外组件拒、变量不一致拒，错误信息逐项定位到行（REQ-WG-A02）
- [ ] 非属主不可见他人资产、不可读写；管理员全可见；越权返回业务错误（REQ-WG-A03）
- [ ] 保存后新对话立即用新内容渲染；修改资产后已发出的历史卡片仍按原样渲染（REQ-WG-A04）
- [ ] 删除被绑定资产被拒并提示解绑；解绑后删除成功（REQ-WG-A05）
- [ ] 后端白名单与前端渲染集合不一致时守护测试失败（REQ-WG-A06）
- [ ] 内置模板启动播种幂等：首次插入、重启不重复、不覆盖（REQ-WG-B01）
- [ ] 内置行无法编辑/删除，仅可查看与复制（REQ-WG-B02）
- [ ] 复制生成独立资产：三件套一致、属主为当前用户、可编辑可绑定（REQ-WG-B03）
- [ ] 绑定候选中不出现内置行与他人资产（REQ-WG-B04/REQ-WG-C02）
- [ ] 绑定 N:N 成立：一资产可挂多应用、一应用可挂多资产；禁用绑定不注入不渲染（REQ-WG-C01）
- [ ] 单应用绑定到 10 条后添加被拒并提示上限（REQ-WG-C03）
- [ ] 无应用编辑权限的用户无法管理绑定（REQ-WG-C04）
- [ ] 挂启用绑定的对话上下文含清单且可调用 render_widget；纯直聊无注入、无该工具（REQ-WG-D01）
- [ ] 调用绑定集合外的资产标识被拒且回灌错误文本（REQ-WG-D02）
- [ ] 校验通过的调用返回定格快照（标识/替换键/名称/模板/数据五要素）（REQ-WG-D03）
- [ ] 数据不符合数据结构的调用收到错误文本且对话继续、模型可自纠（REQ-WG-D04）
- [ ] 超 32KB 数据走失败路径；清单注入超 5000 字符被截断（REQ-WG-D05）
- [ ] 含快照消息落库后，重开会话历史可按快照渲染卡片，删除资产不影响历史渲染（REQ-WG-D06）
- [ ] 同一替换键的两次快照，前端只保留一张卡且为新快照（REQ-WG-D06 过程反馈）
- [ ] 全程无新增对话流事件类型（REQ-WG-D07）
- [ ] 卡片提交推进新对话轮：模型收到回传负载并能基于其继续（REQ-WG-E01）
- [ ] 回传产生可见用户消息（文本摘要）且结构化负载入上下文（REQ-WG-E02）
- [ ] 超 16KB 回传被拒并返回业务错误（REQ-WG-E03）
- [ ] 回传沿用通道既有鉴权，无新鉴权面（REQ-WG-E04）
- [ ] 资产表与绑定表 DDL 在 SchemaInitializer 与 schema.sql 双处一致（约束）

## 测试策略 {#testing}

经控制器/服务层公共接口与引擎工具缝测试，LlmService 与沙箱全部 mock（沿用 AgentEngine 既有测试模式）。重点用例族：

①三档校验逐档取样（坏 JSON / 白名单外组件 / 缺必填属性 / 变量不一致 / 默认值不符），断言行级错误（4.1）。②播种幂等——两次启动只此一份且不覆盖（4.2）。③复制语义——三件套深拷贝、属主归属、内置标识不带出（4.2）。④绑定上限与禁用开关——10 条边界、禁用后注入与渲染双链失效（4.3）。⑤工具校验链——绑定集合外标识拒绝、数据结构不符回灌、快照五要素定格（4.4，本特性最重的正确性断言）。⑥体积护栏——32KB/5000 字符阈值两侧取样（4.4）。⑦回传编排——可见消息合成、负载标注块注入、16KB 拒绝、通道鉴权沿用（4.5）。⑧历史回放——落库消息的工具记录含快照、资产删除后仍可渲染（4.4）。⑨DDL 双处一致性守护测试（对齐 SkillDdlParityTest 先例）。⑩白名单双份一致性守护测试（4.1 REQ-WG-A06）。
