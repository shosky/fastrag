# 新建对话与会话中心（new-conversation） — 需求规格

> 2026-09-25 由 idd-spec 依据 grill 裁决记录（`fastrag/.tmp/idd-new-conversation-grill-decisions.md`，全 5 批 21 项 resolved）编写。
> 对齐目标：WeKnora v0.8.2 新建对话设计；对比调研全文见 [../research/weknora-vs-fastrag.md](../research/weknora-vs-fastrag.md)。

## 1. 特性与范围

本特性把 FastRAG 的对话体验从"应用运行"（先配置应用、在应用内对话）改造为 WeKnora 式"新建对话"（session-first）：**会话成为一等公民，用户不预配应用即可直接开聊；"应用"从对话容器降级为会话上的可选预设**（对齐 WeKnora 会话请求态中 agent_enabled + agent_id 旋钮语义，WeKnora internal/types/session.go:334-347）。范围覆盖：新建对话与会话中心（按用户全量的统一会话入口）、会话请求态（最后一次输入范围的持久化与恢复）、知识库直聊通道（不挂应用的对话执行）、应用预设挂载（带应用配置的新建对话）、会话能力面（LLM 起标题、停止生成、清空消息、批量删除、置顶）、消息引用落库（历史可回看的检索来源），以及旧应用对话通道的废弃保留。执行链复用 app-center 域的对话编排器与会话账本（AppDialogOrchestrator / AppConversationLedger，见 [../design/app-center.md](../design/app-center.md) §1），本特性不新建编排器。

## 2. Out of Scope

- 拒绝意图分类与"闲聊零检索"：对话每次都执行检索（知识库范围为空时除外）；查询理解（改写/同义扩展/意图）归 retrieval 域演进（其查询改写现为已登记 stub）。
- 拒绝流式事件模型改造（StreamManager / 断线重连 / 多副本续流）：归 agent 域立项；停止生成第一版为单实例语义。
- 拒绝会话附件 / 临时文档：依赖 file-ingestion 临时解析通道，另立特性链。
- 拒绝 fork / rewind（会话分叉与回滚）：登记为本域后续独立增强。
- 拒绝 web 搜索能力：请求态仅预留开关字段，不做实现（FastRAG 无该能力）。
- 拒绝工具 / MCP / 技能在直聊通道的运行时消费：~~请求态仅存储相关 ID，能力消费仍经应用绑定装配~~ **演进（2026-09-25 用户裁决）**：直聊消费 tool/mcp/skill ID（REQ-B02）；外部数据库仍不对直聊开放（安全面）。
- 拒绝为直聊引入新权限键或菜单权限种子：资源授权下沉到知识库检索时执行。
- 拒绝检索管线本身的增强（RRF 融合、防截断、MMR 等）：属 retrieval 域（见对比报告 P0 建议）。

## 3. 领域术语

- **应用（App）**：CONTEXT.md 条目（含 2026-09-25 降级注记——从对话容器降级为会话可选预设）。
- **知识库权限（KB ACL）**、**SSE**、**统一响应（ApiResponse）**：CONTEXT.md 条目。

## 4. 功能需求

### 4.1 会话一等公民与会话中心

会话不再依附应用而存在，这是整个改造的地基：用户从会话中心发起新建对话，选好知识库范围与模型即可开聊；应用退为会话的一个可选挂载项。会话中心取代"应用内会话列表"成为对话的唯一入口，存量按应用创建的会话不经迁移自然并入同一视图。

- **REQ-A01**：登录用户可直接创建会话开聊，创建会话不要求预配应用或知识库（二者均可选，缺省为空请求态的直聊会话）。〔证据：裁决 2026-09-25 批次 1/2；WeKnora routes_chat.go:53 会话独立路由组〕
- **REQ-A02**：会话可全程不挂应用完成多轮对话（知识库直聊）；会话的存在与访问不依赖任何应用。〔证据：CONTEXT.md「知识库直聊」条目〕
- **REQ-A03**：会话中心按用户全量列出会话：置顶优先、其余按更新时间倒序，每条带来源标记（直聊 / 来自应用 X）；存量按应用创建的会话自然并入。〔证据：裁决批次 5-3；WeKnora routes_chat.go:56 按租户/用户全量列会话〕
- **REQ-A04**：重开会话恢复最后一次请求态（知识库范围、模型、挂载应用），供输入框状态还原；无请求态的存量会话降级为"挂应用则用应用配置、直聊则空范围"。〔证据：裁决批次 1-3、5-3；WeKnora session.go:95-101 重开恢复 LastRequestState〕

### 4.2 会话请求态与能力范围

请求态是"新建对话"的配置载体：用户在对话过程中选定的范围（知识库、模型、挂载应用）随对话自动固化到会话上，下次打开即恢复。字段形状一次建齐对齐 WeKnora，运行时消费范围第一版刻意收窄。

- **REQ-B01**：请求态在每次成功对话后自动固化（保存最后一次输入范围），涵盖挂载应用及其开关、知识库 ID 列表、模型、工具/MCP/技能 ID 列表、web 搜索开关（预留）。〔证据：裁决批次 1-3、2-2；WeKnora session.go:96-101 "Persisted on every successful POST"〕
- **REQ-B02**：第一版运行时仅消费知识库范围、模型与挂载应用；工具/MCP/技能 ID 与 web 搜索开关仅存储、不参与执行。〔证据：裁决批次 2-2〕**演进（2026-09-25 用户裁决，对齐 WeKnora 直聊工具）**：tool/mcp/skill ID 转为**直聊消费**——装配进执行上下文（与绑定同路径）；webSearchEnabled 仍仅存不消费。
- **REQ-B03**：知识库授权在对话请求时逐 KB 校验（viewer 及以上可见即可对话），无权限的知识库跳过并记告警，不中断整次对话。〔证据：裁决批次 2-4；WeKnora knowledgebase_search.go:192-201 检索时逐 KB 授权；与 app-center REQ-C04 单库失败不中断同构〕

### 4.3 知识库直聊通道

直聊是"不配应用也能聊"的执行路径：范围取请求态，缺省取内置常量，全链复用现行对话编排（安全拦截→落库→检索→装配→委派执行引擎→输出过滤→落库）。它与挂载应用的对话共享同一条编排链，只差配置来源。

- **REQ-C01**：不挂应用的对话：检索范围取请求态知识库列表（空列表 = 不调用检索直接生成）；系统提示词与执行预算用内置缺省值（与现行编排器缺省一致：缺省 prompt、maxTokens=2048、temperature=0.7）。〔证据：裁决批次 2-3；app-center REQ-B02/E10 缺省值〕
- **REQ-C02**：直聊复用现行对话编排链与 SSE 事件词汇，不另建编排器、不新增事件类型。〔证据：裁决批次 1-4；design/app-center.md §3 缝 1 防双实现漂移〕
- **REQ-C03**：直聊每次对话都执行检索，无意图分类短路（知识库范围为空时除外，见 REQ-C01）。〔证据：裁决批次 4-3；app-center spec §2 检索策略 Out of Scope〕
- **REQ-C04**：直聊默认启用敏感词输入拦截与输出过滤（安全缺省开，与现行 REQ-D01 同语义；此为与 WeKnora 的显式偏离——WeKnora 无敏感词体系，FastRAG 守安全默认取向）。〔证据：裁决批次 4-2；app-center REQ-D01〕
- **REQ-C05**：模型路由：请求态指定的模型优先；未指定时回退现行模型路由链（app-center REQ-E06 四级回退语义不变）。〔证据：裁决批次 2-2；app-center REQ-E06〕

### 4.4 应用预设挂载

挂载应用是"应用运行"在新模型下的形态：应用配置整体作为预设注入，老用户不丢任何能力。挂载与直聊的范围来源互斥，避免"应用绑定"与"请求态选择"双源合并的歧义。

- **REQ-D01**：会话可挂载应用作为预设：对话按该应用现行配置执行（五类绑定、系统提示词、执行预算、安全策略、模型路由），行为与现行应用对话一致。〔证据：裁决批次 1-2；WeKnora session.go:335-336 agent_enabled + agent_id 旋钮〕
- **REQ-D02**：范围来源互斥——挂载应用时知识库范围以应用绑定为准（请求态知识库列表不消费）；不挂应用时以请求态为准。〔代裁 2026-09-25，可推翻：裁决记录未细化挂载与请求态并存的优先级，取最简互斥语义避免双源〕
- **REQ-D03**：存量会话（挂应用、无请求态）在会话中心正常呈现，恢复对话按挂载应用配置执行。〔证据：裁决批次 5-3〕

### 4.5 会话能力面

WeKnora 会话体验中已被用户验证的高频能力，本版补齐四件低成本项、推迟两件重能力项（fork/rewind、附件，见 Out of Scope）。

- **REQ-E01**：LLM 起标题：可对会话显式触发起标题，基于会话消息生成；失败或无可用模型时回退现行截断首问逻辑（首问截 30 字，app-center REQ-E04 语义保留为兜底）。〔证据：裁决批次 3-1；WeKnora routes_chat.go:60 generate_title〕
- **REQ-E02**：停止生成：进行中的流式对话可被停止；停止时已生成的部分答案按现行超时部分落库语义处理（过滤后落库），流正常关闭。〔代裁延伸 2026-09-25：落库语义复用 app-center REQ-E12；裁决批次 3-2；WeKnora routes_chat.go:66 stop〕
- **REQ-E03**：清空会话消息：删除该会话全部消息（含已软删）但保留会话本身，消息计数归零。〔证据：裁决批次 3-3；WeKnora routes_chat.go:59 清空消息〕
- **REQ-E04**：批量删除会话：一次删除多个会话，消息处理与单个删除一致（物理级联删，app-center REQ-E14 同语义）。〔证据：裁决批次 3-3；WeKnora routes_chat.go:54 批量删除〕
- **REQ-E05**：会话可置顶 / 取消置顶；会话中心列表置顶优先（REQ-A03）。〔证据：裁决批次 3-3；WeKnora session.go:90-93 is_pinned〕

### 4.6 消息引用落库

现状引用只在流内推一次（sources 事件），重开历史即成裸文本——这是"重开对话"体验成立的前提缺口。引用随消息持久化后，历史回看才带有来源。

- **REQ-F01**：助手消息落库时保存本次检索引用集合（知识库、文件、分片定位、相似度），与流内 sources 事件同源同内容；无检索命中时存空。〔证据：裁决批次 4-1；app-center REQ-E08 sources 字段面、design §3 缝 2 SearchResultItem〕
- **REQ-F02**：会话历史查询返回消息引用，重开会话可回看每条回答的检索来源。〔证据：裁决批次 4-1；WeKnora messages.knowledge_references〕

### 4.7 兼容、迁移与权限

旧通道不删、机器通道不堵、存量数据不动——改造对现有消费方零破坏。

- **REQ-G01**：现行应用对话通道整体保留并标记废弃，行为不变（app-center REQ-E01~E15 继续适用于该通道），下线另行排期、不由本特性执行。〔证据：裁决批次 5-1〕
- **REQ-G02**：新通道支持 API Token：绕过会话归属校验（机器对机器，现行 app-center NFR-02 语义），知识库授权仍逐 KB 执行（REQ-B03）。〔证据：裁决批次 5-2；WeKnora routes_chat.go:50-51 apiKey 会话组〕
- **REQ-G03**：存量数据零迁移：现有会话数据不动，"会话可不挂应用"仅对新会话生效。〔证据：裁决批次 5-3〕
- **REQ-G04**：新通道端点鉴权 = 登录即可（JWT / API Token），不引入应用级权限注解或新权限键；资源授权在知识库检索时执行（REQ-B03）。〔证据：裁决批次 5-4；WeKnora routes_chat.go:51 sessions 组 Viewer 角色〕

## 5. 非功能约束

- **NFR-01**：统一响应宪法适用：新端点全部经 ApiResponse 包装，分页必须 `PageResult{list,total,page,pageSize}`——不得复现 listConversations 的 `{total,items,page,size}` 违例（design/app-center.md §5 已仲裁为偏离）。〔证据：CONTEXT.md 统一响应条目〕
- **NFR-02**：本特性涉及的全部 DDL 变更（会话表应用关联放宽可空、请求态存储、消息引用存储）保持 `init-scripts/schema.sql` ↔ `SchemaInitializer` 双处同步。〔证据：AGENTS.md 硬约定〕
- **NFR-03**：新通道对话流纳入现行 SSE 并发与线程池约束（app-center NFR 裁决：≤200 连接/实例、有界线程池）；停止生成后无孤儿流（emitter 关闭、不再有该次对话的后续推送）。〔证据：app-center spec §5 并发 SLA 决议；裁决批次 3-2〕

## 7. 测试策略

经公共接口（新通道对话端点、会话中心端点、会话能力端点 + 旧通道回归）测试，优先级：

1. **会话生命周期状态机**（最高）：新建→对话（请求态固化）→重开恢复→置顶→清空→批量删除，每步断言库中行与接口返回的可观测结果；存量会话（有 app_id、无请求态）的降级恢复单列用例。
2. **直聊编排分支**：空 KB 不调检索（mock RetrievalService 断言零调用）、无权 KB 跳过并告警、缺省预算装配断言、敏感词开关两态对照、停止后部分落库且 emitter 关闭。
3. **应用预设挂载**：挂载时五类绑定生效且请求态 KB 不消费（互斥断言）；请求态模型优先于应用模型的优先级断言（REQ-C05 vs REQ-D01 交界）。
4. **消息引用**：落库内容与 sources 事件同一数据源的一致性断言；历史接口返回引用；无命中存空。
5. **兼容回归**：旧通道现行 REQ-E01~E15 抽样回归；API Token 旁路（归属校验绕过 + KB 授权仍生效）；升级前后存量表数据 diff 为空。
