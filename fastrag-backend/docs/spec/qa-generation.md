# 问答对提炼（qa-generation）— 需求规格

> 裁决来源：fastrag/.tmp/idd-qa-generation-grill-decisions.md（2026-09-26，四批 D1-D14 + 配置入口 P1-P6，全部已决）。
> 本特性清偿 qa-pairs spec REQ-E03 登记的「问答对提取流水线」GAP，并修订其 REQ-D04 召回口径（见 4.3）。

## 1. 特性与范围

问答对提炼为知识库文件提供基于 LLM 的「问题—答案」自动生成能力：以父分片为提取单位，从分片内容提炼完整问答对，经质量闸门后落知识库问答对数据（source=ai，初始 draft），经人工确认后进入检索 qa 召回通道。触发路径两条：文件级手动触发（单文件与多选批量，三个前端入口共用同一参数集），以及 qa 处理模式文件在摄入流水线完成后的自动触发（参数于上传时指定、随文件持久化）。本特性与人工问答对管理（qa-pairs）共享同一张问答对数据与同一套确认状态机，仅新增「ai 来源」的产出与准入规则。

## 2. Out of Scope

- **知识库级自动提炼开关 / KB 级缺省提炼配置**：提炼只能逐文件显式触发（qa 模式上传即逐文件显式 opt-in），避免全库无差别 LLM 消耗。〔裁决 D3③/D7〕
- **只生成问题不生成答案的模式**（WeKnora Doc2Query 形态）：qa 召回通道消费 Q/A 拼接文本，答案缺位则通道价值不成立。〔裁决 D1〕
- **LLM 自检/二次审稿质量门**：静态闸门（去重、护栏）加人工确认已兜底。〔裁决 D9〕
- **断点续跑**：失败整文件重跑，不做分片级进度恢复状态机。〔裁决 D6〕
- **多级审核流**（提交→审核→驳回）：复用既有 draft→confirmed 单向确认，无撤销路径。〔裁决 D10〕
- **问答对向量化与 Milvus 入库**：qa 召回维持关键词模糊匹配通道（与 qa-pairs spec §2 口径一致）。
- **生成任务的实时推送**：任务状态经轮询查询。〔裁决 D13〕
- **问答对导出为训练语料**。

## 3. 领域术语

- **问答对提炼（QA Generation）**、**召回准入（Recall Admission）**、**父分片（Parent Chunk）**、**重新分片（Re-chunk）**：见 [CONTEXT.md](../CONTEXT.md)。
- **QA 对（KbQaPair）**：人工/AI 维护的问答知识单元，来源 manual/ai，状态 draft/confirmed。〔CONTEXT.md + qa-pairs spec §3〕
- **qa 处理模式**：文件处理模式枚举中的 qa 取值（历史注释「问答对提取」），语义为「该文件以问答提炼为目的入库」，由本特性兑现其消费端实现。〔KbFile.java:58 ‹CERTAIN›〕
- **统一响应（ApiResponse）**：业务错误 = HTTP 200 + body.code。〔CONTEXT.md〕

## 4. 功能需求

### 4.1 触发与配置

问答对提炼的入口分「手动」与「自动」两类。手动入口有三个（文件详情页按钮、文件列表行内菜单、多选批量操作栏），共用同一参数集：每父分片生成条数、自定义指令、重跑模式、模型。自动入口服务于 qa 处理模式文件：上传时选定模式并指定参数，摄入完成后系统自动提炼。所有触发共享一条互斥约束：同一文件的生成任务同时只有一个。

- **REQ-A01**：用户可对单个文件发起问答对提炼，可选参数：每父分片生成条数（1-10，缺省 3）、自定义指令（自由文本，缺省空）、重跑模式 replace（缺省）/append、模型（缺省系统默认模型路由）。〔裁决 D4/D6/D11〕
- **REQ-A02**：文件列表提供单文件快捷入口与多选批量入口；批量提炼以相同参数为每个选中文件建立独立任务，单个文件的失败不影响其余文件的任务。〔配置入口 P2/P3〕
- **REQ-A03**：用户上传选择 qa 处理模式时指定提炼参数（条数/自定义指令/模型；无重跑模式——首次生成本身即 replace 语义），参数随文件持久化；该文件摄入流水线完成后系统按该参数自动触发一次提炼。〔裁决 D3②/D7；清偿 qa-pairs REQ-E03〕
- **REQ-A04**：同一文件的生成任务进行中时，再次触发（手动或自动）被拒绝且不产生副作用；该判定持久化，服务重启后仍有效。〔裁决 D5/D13〕
- **REQ-A05**：replace 模式在**任务开始时**删除该文件 ai 来源的既有问答对（manual 问答对一律不触碰）；append 模式保留既有问答对，仅追加新产出。**逐片落库（2026-09-27 修订）**：产出不再缓冲至任务收尾，而是每分片提炼完成即落库（问答对页实时可见草稿；ai 草稿本就不参与召回，中途可见不影响检索）；replace 的删旧相应提前至任务开始——中途崩溃残留部分新对，由再次 replace 自愈（可见性优先于崩溃窗口保护，产出可再生）。〔裁决 D6；2026-09-27 修订〕

### 4.2 生成过程与质量闸门

生成以父分片为单位逐片调用 LLM：父分片按标题层级聚合、逻辑完整，天然支持逐片并行与按片失败隔离。生成内容受三条约束锚定原文，落库前经两道零 LLM 成本的静态闸门（去重、护栏），任何一片的失败只记入统计、不扩散为任务失败。

- **REQ-B01**：提取单位为父分片，**存量兼容（2026-09-27 修订）：文件无父分片（旧管道产物全为文本分片）时回退全部文本分片**（排除图片占位）；每条产出关联源文件（含文档名）与源分片，问答对随源文件展示与筛选。〔裁决 D2/D12；修订=无父分片回退〕
- **REQ-B02**：生成结果须满足三条约束：问题自包含（脱离原文语境可理解、模拟真实用户问法）；答案仅陈述源分片内的内容；分片不含可答题材料时该分片产出零条。〔裁决 D8〕
- **REQ-B03**：LLM 响应解析对非标准输出容错——markdown 围栏包裹、前后夹杂说明文本、内容截断均不得中断任务；解析失败记该分片失败。〔裁决 D8；容错先例 BenchmarkResponseParser〕
- **REQ-B04**：单父分片的模型调用失败重试 1 次，仍失败则跳过该分片并计入统计，不阻断同文件其余分片；任务结束产出总/成功/失败分片统计。〔裁决 D6〕
- **REQ-B05**：落库前静态闸门：①问题按「全角→半角、trim、压缩连续空白」归一化（与 Excel 导入同一口径）后，文件内重复及与库内既有问答对重复的产出跳过；②问题少于 5 字或答案少于 2 字的产出丢弃；闸门拦截数计入任务统计。〔裁决 D9；归一化口径同 qa-pairs REQ-C05〕

### 4.3 审核与召回准入

AI 产出落库即为草稿，不直接生效；用户经既有确认操作将其置为已确认。确认的语义因来源而分叉：对 manual 问答对维持「管理标记」现状（创建即可召回），对 ai 问答对则具备「生效准入」语义（确认后才可召回）——这是本特性对 qa-pairs REQ-D04 的正式修订。

- **REQ-C01**：AI 产出落库时来源为 ai、状态为 draft；确认操作复用既有单向 draft→confirmed 转移，无撤销确认路径。〔裁决 D10；qa-pairs REQ-B01〕
- **REQ-C02**：qa 召回通道的准入规则为「manual 来源，或状态 confirmed」：ai 来源 draft 不参与召回；manual 问答对（无论状态）召回行为与现状完全一致。〔裁决 D10 2026-09-26；修订 qa-pairs REQ-D04〕
- **REQ-C03**：QA 管理面板展示来源 ai 标记，来源筛选包含 ai；AI 问答对与 manual 问答对使用同一编辑、删除、确认操作面。〔配置入口 P5〕

### 4.4 任务状态与溯源

系统为每个文件维护最近一次提炼任务的可见状态（进行中/成功/部分成功/失败），使分钟级的后台生成对用户可观测；同时问答对提供源分片级溯源，支撑 REQ-C02 要求的人工确认核对。溯源在源分片消失（重切重建、手工删片）后降级而非失效。

- **REQ-D01**：每个文件保留最近一次提炼任务的状态记录：状态（进行中/成功/部分成功/失败，部分成功对应存在被跳过分片的完结）、总/成功/失败分片计数、参数快照、错误信息、时间；新任务覆盖旧记录（每文件仅一份）。〔裁决 D13〕
- **REQ-D02**：用户可在触发后随时查询该文件的任务状态与分片统计（轮询）；触发操作记录操作审计日志。〔裁决 D13〕
- **REQ-D03**：问答对可定位其源父分片（在分片管理中跳转查看）；源分片因重切重建或手工删除不存在时，溯源降级为仅文件级（不报错、不清理问答对）。〔裁决 D12〕

### 4.5 生命周期级联

级联口径除下述显式条款外，全部沿用 qa-pairs spec §4.5 既有裁决，ai 来源与 manual 来源同等适用：删除知识库级联清理（qa-pairs REQ-E01）、删除文件级联清理（REQ-E02）、跨库移动问答对不随迁（REQ-E05）。

- **REQ-E01**：qa 处理模式文件禁止重切（既有守卫）；chunk 模式文件重切后其问答对（manual 与 ai）全部保留，悬空分片引用按 REQ-D03 降级展示。〔裁决 D12；qa-pairs REQ-E04〕
- **REQ-E02**：qa 处理模式文件的提炼参数随文件存续：跨库移动后参数随文件前往目标库，源库问答对按既有裁决不随迁。〔裁决 D14；qa-pairs REQ-E05〕

## 5. 非功能约束

- **异步与持久化**：提炼受理后异步执行、立即返回，不阻塞页面交互；已受理任务不因服务重启丢失（重启后任务可继续或明确失败，不得无声消失）。〔裁决 D5〕
- **吞吐约束**：提炼的模型调用并发受上限约束，与图谱构建、在线检索共用模型服务时相互不挤兑（满载提炼进行中，图谱构建仍可正常完成）。限流机制归设计层。〔裁决 D5〕
- **召回延迟基线**：qa 召回通道 P95 ≤ 200ms 基线延续（qa-pairs spec §5）；准入条件增加不得显著劣化该基线。
- **权限与审计**：触发提炼、编辑/删除/确认问答对要求 editor 及以上角色并记操作审计；任务状态查看要求 viewer 及以上；全部端点鉴权与全后端 KB ACL 一致。〔qa-pairs REQ-A05 同口径〕
- **DDL 双处同步**：本特性新增持久化结构（分片溯源关联、qa 模式参数、任务状态记录）的 DDL 必须在 SchemaInitializer 幂等增补与 init-scripts/schema.sql 全量脚本双处同步，并列为验收项（历史漂移教训：idx_content_fulltext 单侧、agent 表缺失）。〔裁决 D14〕

## 6. 验收清单

- [ ] 手动触发缺省参数生效：条数 3、模式 replace、模型走系统默认路由（REQ-A01）
- [ ] 条数传 0 或 11 被业务错误拒绝（REQ-A01）
- [ ] 批量选中 N 个文件产生 N 个独立任务，其中 1 个文件失败其余照常完成（REQ-A02）
- [ ] qa 模式文件摄入完成后自动生成，所用参数与上传时指定一致（REQ-A03）
- [ ] 任务进行中重复手动触发被拒绝且无副作用；服务重启后进行中判定仍生效（REQ-A04）
- [ ] replace 完成后该文件旧 ai 对全部消失、manual 对不变；append 完成后新旧共存（REQ-A05）
- [ ] 每条产出可关联到源文件与源父分片（REQ-B01）
- [ ] 纯目录/图表类无可答题材料的父分片产出零条（REQ-B02）
- [ ] LLM 返回带 markdown 围栏与前后说明文本的响应被正确解析；截断响应使该分片记失败且任务继续（REQ-B03）
- [ ] 单分片失败自动重试 1 次后跳过，任务统计与实际一致（REQ-B04）
- [ ] 全角问题与库内半角同文问题判重跳过；4 字问题被护栏丢弃；拦截数出现在任务统计（REQ-B05）
- [ ] AI 产出落库为 source=ai + draft；确认后为 confirmed；确认无撤销路径（REQ-C01）
- [ ] AI draft 不出现在检索结果；确认后出现；manual draft 正常出现（REQ-C02）
- [ ] QA 面板来源筛选含 ai 且标记正确（REQ-C03）
- [ ] 任务状态四态与分片统计正确；同一文件二次触发覆盖旧任务记录（REQ-D01）
- [ ] 触发后可轮询到状态；触发动作出现在审计日志（REQ-D02）
- [ ] chunk 模式文件重切后问答对保留，源分片跳转对已重建分片降级为文件级且不报错（REQ-D03、REQ-E01）
- [ ] qa 模式文件请求重切被拒绝（REQ-E01）
- [ ] 删除文件后该文件 ai 与 manual 问答对均级联清理（REQ-E02、qa-pairs REQ-E02）
- [ ] 触发/删除/确认要求 editor 角色并记审计；viewer 触发被拒绝（NFR）
- [ ] 新增表/列在 SchemaInitializer 与 schema.sql 双处存在且一致（NFR）

## 7. 测试策略

经由公共接口（提炼服务与控制器、QaPairService、RetrievalServiceImpl 既有测试缝）测试，LLM/Milvus/Embedding/Rerank 全部 mock（沿用 RetrievalServiceImplTest 模式），MySQL 写入走真库（MyBatis-Plus）：①触发与参数校验——缺省值、越界拒绝、互斥、replace/append 分叉（4.1）；②生成编排——父分片迭代、失败重试与跳过、统计准确性（4.2，mock LLM 按片返回可控结果）；③解析容错用例族——围栏、前后缀说明、截断、空响应（纯函数，仿 BenchmarkResponseParserTest）；④质量闸门——归一化判重（复用 ExcelQaPairImporter 口径用例）、护栏阈值边界（4.2）；⑤召回准入三分支——ai draft 排除、ai confirmed 命中、manual draft 命中（4.3，本特性最重要的回归点）；⑥任务状态机——四态转移与覆盖语义（4.4）；⑦级联一致性——重切保留、qa 模式重切守卫、文件删除级联（4.5，联合 qa-pairs 既有用例族）。

## 8. UI Decisions

布局与入口在 grill 会话裁决（配置入口 P1-P6），全部沿用既有组件先例、无结构性分歧，未产原型变体：

- **触发入口三处**：文件详情页页头（「重新分片」按钮旁）、文件列表行内菜单（仿「AI分片」项）、批量操作栏（仿「批量打标」）——三处共用同一个参数对话框（条数/自定义指令/replace·append/可选模型）。
- **上传对话框**：qa 处理模式选项解除禁用（现有 disabled + 「开发中」tooltip 的预留位），选中时展开条数/自定义指令/模型参数区块。
- **QA 管理面板**：来源标签映射补 ai，来源筛选控件已存在直接纳入。
- **已拒绝**：知识库级设置卡片（图谱设置浮层模式）——qa 模式为逐文件 opt-in，文件级参数已覆盖，库级开关已由裁决 D3③ 排除。
