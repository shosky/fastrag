# 对话审计采用引擎埋点与终态批量落表

**Date:** 2026-10-15
**Status:** Accepted（grill 裁决 D3/D9，2026-10-14）

## 背景 {#context}

对话审计要同时记录每次 LLM 调用（请求/响应/思考/用量）与每次工具执行（参数/原始输出/耗时）。采集点有两个候选：LlmService 是全系统 12 个调用入口的单点，但拿不到会话上下文、也看不到工具执行；AgentEngine 工具循环是唯一同时看得见两类细节又持有运行上下文的位置。写入时机上，单轮对话可产生 20+ 个步骤，落表策略直接决定对话延迟与审计完整性。

## 决策 {#decision}

埋点放 AgentEngine 双执行入口（executeStream:235 / executeSync:562）的观察点，运行期内存收集、终态一次性批量落表，落表失败仅告警、绝不影响对话（对齐 agent NFR02）。

## 已考虑的替代方案 {#alternatives}

**LlmService 全局单点拦截** — 拒绝：拿不到会话上下文，需 ThreadLocal 跨层穿透（异步线程传播易漏）；记不到工具执行，对话审计语义不完整；且 12 个入口全记会把 QA 提炼/图谱抽取等非会话调用灌进审计表，违背范围裁决（grill D4）。

**逐条同步 INSERT** — 拒绝：每步一次同步写库，单轮 20+ 步的写库延迟直接叠加进对话响应，违反「落表非关键路径」约束。

**运行中逐条异步写（MQ/线程池）** — 拒绝：为审计单独引入异步通道带来乱序、并发与幂等问题，而收益仅是把崩溃丢失窗口从「一轮」缩到「一步」——SSE 事件本就全程易失，该收益不值得复杂度。

## 后果 {#consequences}

对话关键路径零写库，采集覆盖天然等于引擎全部调用方（会话双通道 + 独立运行，无遗漏入口）。代价：进程在运行终态前崩溃丢当轮审计（与 SSE 事件易失同级，已在 spec REQ-CT-C03 登记为已接受代价）；采集正确性完全依赖引擎观察点接线完整，双入口遗漏即整段缺失——验收清单以三入口各一轮对话兜底。
