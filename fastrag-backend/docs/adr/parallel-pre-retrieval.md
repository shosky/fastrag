## 背景 {#context}

应用对话的检索策略经历三次摆动：

1. **预检索管线**（2026-09-30 前无关条件预检索）——每轮无条件检索，无关问题白付延迟与噪音上下文，被「全 agentic 化」移除（非正式决策，仅存于代码注释，无 ADR）。
2. **全 agentic 化**（2026-09-30）——检索完全靠模型自主调 query_kb。8B 级模型该查不查（把领域题判成常识题），且不检索时按提示词格式幻觉输出 `[文件名]` 引用。
3. **强制 tool_choice 检索**（2026-10-19，R4）——首轮指名强制 query_kb，结构性消除该查不查。但引入反向代价：无关问题（问候/算式/能力问句）也被强制检索，多付**一整轮 LLM 往返**；豁免白名单（问候→算式→能力问句）持续打地鼠，不可通用。

同一时期的「你能干什么？」日志（69 工具 / 118KB 请求体，单轮 25s）量化了代价：强制检索的真实成本不是检索本身（亚秒级），而是**多一轮全量上下文的 LLM 往返**。

## 决策 {#decision}

**首轮模型调用前同步执行绑定知识库预检索（亚秒级），结果以 [cN] 句柄 system 附加块注入首轮上下文；模型不再被强制调工具。**

- 移除 R4 强制机制整体：`BaseContext.forceFirstRetrieval`、`FORCED_QUERY_KB_TOOL_CHOICE`、`resolveToolChoice`、tool_choice 指名降级包装；豁免白名单逻辑改造为**预检索豁免**（跳过注入而非跳过强制）。
- `query_kb` / `list_kbs` 工具保留：首轮资料已注入，模型仍可自主二次检索（换词重试、深挖）；句柄编号与预检索共享连续。
- 预检索失败或空结果 fail-open：不注入、对话照常（等价退化为纯 agentic 旧行为）。
- 作用域：机制实现在引擎层（PreRetrievalMiddleware，IF-003），本期仅 app-chat 编排置开关；知识库直聊后续复用。

本决策取代：2026-09-30「全 agentic 化移除预检索」的非正式决策，与 2026-10-19 R4 强制检索机制（后者未提交即废弃）。

## 后果 {#consequences}

- **正面**：知识库问题首答延迟从「一整轮 LLM 往返」降为「一次亚秒级检索」；无关问题成本降为一次可豁免的亚秒检索；该查不查与幻觉引用被结构性消除；引用来源统一走句柄协议（消息引用/前端卡片复用既有通道）。
- **负面**：未命中豁免的无关问题会注入噪音分片（靠豁免清单缓解，非完美，泄漏可接受——噪音分片 ≈ 5000 字符，远小于一轮往返）；检索域不可用时退化为旧行为且无降级提示。
- **中立**：检索通道从一条（工具）变为两条（预检索 + 工具），句柄续号与来源合并逻辑须跨通道共享；「跟随应用绑定模型做检索改写」的正交问题不受本决策影响，另行处理。
