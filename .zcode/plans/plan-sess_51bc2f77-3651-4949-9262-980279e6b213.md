# 组织数据隔离改造计划

## 目标
知识库按组织隔离：**同组织成员自动可见本组织知识库（viewer 兜底）**，ACL 用于跨组织分享/提升角色；**分类完全按组织隔离**（每个组织独立分类）；分类管理仍由 kb_admin 统一负责。

## 权限模型（最终）
| 用户 | 知识库可见性 | 分类可见性 | 分类管理 |
|---|---|---|---|
| super_admin | 全部 | 全部 | ✅ |
| kb_admin | 全部（管理视角） | 全部（含未分配） | ✅（admin:system，创建时指定组织） |
| 普通用户 | 本组织所有库（viewer）∪ ACL 授权库 | 仅本组织分类 | ❌ 只读 |
| 无组织用户 | 仅 ACL 授权库 | 无分类可见 | ❌ |

角色解析优先级：ACL 记录（Redis）> 同组织兜底 viewer > 拒绝。跨组织分享的用户角色完全由 ACL 决定。

## 一、数据模型（SQL）
新增 `init-scripts/migrate_org_isolation.sql`（幂等）：
```sql
ALTER TABLE kb ADD COLUMN org_id VARCHAR(32) NULL;
UPDATE kb k LEFT JOIN sys_user u ON u.id=k.creator SET k.org_id=u.org_id;  -- 存量按创建者回填
ALTER TABLE kb_category ADD COLUMN org_id VARCHAR(32) NULL;  -- 存量分类置 NULL=未分配，仅 kb_admin 可见并分配
```
同步更新 `schema.sql` / `schema-h2.sql` / `data-mysql.sql` / `data-hunan-telecom.sql` 的建表语句（kb、kb_category 加 org_id 列）。

## 二、后端改动

### 1. 安全链路携带 orgId
- `LoginUser`（security）：加 `orgId` 字段
- `JwtUtil.generateToken`：加 orgId 参数写入 claim（重载保留旧签名）
- `AuthServiceImpl.login/getUserInfo/buildLoginResponse`（iam）：登录时把 `user.getOrgId()` 写入 token
- `JwtAuthFilter`：解析 orgId claim 构造 LoginUser

### 2. 新增 KbAccessChecker（security 模块定义接口，knowledge 模块实现）
```java
// fastrag-security/.../service/KbAccessChecker.java
public interface KbAccessChecker {
    KBRole resolveRole(String kbId, LoginUser user);   // ACL 优先，同组织兜底 viewer，无则 null
    List<String> getAccessibleKbIds(String userId, String orgId); // 同组织库 ∪ ACL 库
}
```
`KbAccessCheckerImpl`（knowledge 模块，注入 KnowledgeBaseMapper + KbAclService）。

### 3. KbAuthAspect（security）改造
`@Around` 逻辑：超管/api-token 放行不变；删掉直接读 Redis 的逻辑，改为 `accessChecker.resolveRole(kbId, user)`，null → 403，角色层级比较不变。**同组织用户对组织内库无需 ACL 记录即可访问（viewer）**。

### 4. 实体与查询
- `KnowledgeBase` / `KbCategory` 实体加 `orgId`；`KbDto` 加 orgId 透出
- `KbServiceImpl.create`：`org_id = 当前用户 orgId`（无组织存 null，仅本人+ACL 可见）
- `KbServiceImpl.list` / `getCategories`：可见性改为 `accessChecker.getAccessibleKbIds(userId, orgId)`（替代现在的纯 ACL）
- `KbCategoryController.list/usage`：普通用户只查 `org_id = 我的组织` 的分类；kb_admin/super_admin 查全部（含 NULL）；count 统计基于用户可访问的库
- `HomeController.accessibleKbIds()`：改为 org ∪ ACL（复用 KbAccessChecker）

## 三、前端改动（最小）
- `categories.vue`：编辑/新增对话框加"所属组织"下拉（`getOrgFlat`，kb_admin 用；创建分类时 org_id 必选）；列表可选加组织名列
- 其余页面（KB 表单分类下拉、知识库列表）无需改——后端已按组织过滤
