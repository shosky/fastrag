## 0. 总体架构

```
[Browser]
  ├─ AiChunkPanel.vue            既有,新增 chunk-click emit
  ├─ OnlyOfficeEditorDialog.vue  新增,封装 DocsAPI.DocEditor
  │     ├─ 加载 OO iframe (动态注入 api.js)
  │     ├─ 监听 onSelectionChanged → 手动创建 chunk
  │     ├─ 调用 connector.executeMethod(scrollToPage / setVisibleArea)
  │     └─ 通过 OO Plugin SDK 加载 chunk-boundary 侧边栏
  └─ FilePreviewDialog.vue       Office 分支改为"在线编辑"按钮

[FastRAG backend :8081]
  ├─ GET  /api/kb/{kbId}/files/{id}/onlyoffice/config         新增,KB-auth viewer
  │     └─ 返回 JWT 签名后的 OO 配置
  ├─ GET  /api/kb/{kbId}/files/{id}/onlyoffice/raw?token=…   新增,permitAll
  │     └─ OO 服务端拉原始文件 (验证 OnlyOffice JWT)
  ├─ POST /api/kb/{kbId}/files/{id}/onlyoffice/callback       新增,permitAll
  │     └─ 接收 status=2/6 → 下载新文件 → 替换 → reChunkFile → {error:0}
  └─ POST /api/kb/{kbId}/chunks                                既有,选区→手动 chunk

[OnlyOffice Document Server :8082 (Docker)]   新增服务
  └─ 渲染 Word/Excel/PPT,把 events 转发到 callback
```

**已确认的选型**:OnlyOffice 文件 URL 走专用 `/onlyoffice/raw?token=` 路由(permitAll + 自签 JWT);一次交付四项联动;`docker-compose.yml` 中加入 `onlyoffice-docserver`。

## 2. 后端实现(Phase 1-2)

### 2.1 OnlyOffice JWT 工具
**新文件**:`fastrag-security/src/main/java/com/fastrag/security/util/OnlyOfficeJwtUtil.java`

复用 JJWT 依赖。`signPayload(Object, String)` 返回 base64url;`verifyAndParse(String, String, Class<T>)` 验签并反序列化。用于两个场景:
- `document.url` 的 query token(30 分钟 TTL,含 fileId/kbId)
- `config.token` 字段(签名整个 config 对象)

### 2.2 路由配置
**修改**:`fastrag-security/src/main/java/com/fastrag/security/config/SecurityConfig.java`

在 `permitAll` 列表(约 line 65-69)加入:
- `/api/kb/*/files/*/onlyoffice/raw`
- `/api/kb/*/files/*/onlyoffice/callback`

### 2.3 OnlyOffice Controller
**新文件**:`fastrag-knowledge/.../controller/OnlyOfficeController.java`,基地址 `/api/kb/{kbId}/files`:

| 端点 | 方法 | 权限 | 作用 |
|---|---|---|---|
| `/{id}/onlyoffice/config` | GET | `@KbAuth(KBRole.viewer)` | 返回签名后的 OO config,viewer 读 / editor 写依角色切换 `editorConfig.mode` |
| `/{id}/onlyoffice/raw` | GET | permitAll + 验证 OO JWT | OO 服务端拉原始文件 |
| `/{id}/onlyoffice/callback` | POST | permitAll + 验证 OO JWT | 接收保存回调 |

**Callback 关键逻辑**(对应 status 码):
- `1` (editing) → 返 `{error: 0}`,不下载
- `2` (ready for save) → 下载 `payload.url` → `OnlyOfficeService.onDocumentSaved` → 返 `{error: 0}`
- `3` (save error) → 返 `{error: 1}`
- `4` (closed no change) → 返 `{error: 0}`
- `6` (force save) → 同 status=2
- `7` (force save error) → 返 `{error: 1}`

回调入口必须验证 `payload.token` 签 + 比对 `payload.key` 与 `kb_file` 当前 key(防伪造)。

### 2.4 Service 层
**新文件**:`fastrag-knowledge/.../service/OnlyOfficeService.java`(+Impl)

核心方法:
- `buildEditorConfig(kbId, fileId, user)`:读 `kb_file` → 拼 `document.url`(指向 `/onlyoffice/raw?token=...`)+ `callbackUrl` → 用 `OnlyOfficeJwtUtil.signPayload` 签名整个 config
- `handleCallback(kbId, fileId, payload)`:校验 status/签/key → 下载文件字节流 → 调 `onDocumentSaved`
- `onDocumentSaved(kbId, fileId, bytes)`:见 2.5

**新文件**:`fastrag-knowledge/.../model/OnlyOfficeCallbackPayload.java`(DTO 包含 status / url / key / token / users 等 OO 回调字段)。

### 2.5 文件替换 & 重分片
**修改**:`FileServiceImpl.java` 新增 `replaceOriginalFile(kbId, fileId, byte[] newBytes)`(~15 行):用 fileId 反查 `kb_file.name` 拼出路径,覆盖 `./uploads/{kbId}/{fileId}/{filename}`,更新 `updatedAt`。

`onDocumentSaved` 内顺序:
1. `replaceOriginalFile`
2. `documentParser.parse(bytes)` → `ParseResult`
3. `persistParsedMarkdown(kbId, fileId, parseResult)`(复用 `IngestionConsumer` 中的私有方法,需提升到 `MarkdownService` 或直接拷)
4. `reChunkFile(kbId, fileId, null)`(复用现有方法 `FileServiceImpl.java:313-381`,自动删 Milvus / 删 graph / 删 kb_chunk / 重发 RabbitMQ)

**document.key 策略**:用 `SHA1(fileId + updatedAt)` 哈希生成。文件被替换后 `updatedAt` 改变 → key 改变 → OO 下次打开强制 reload。

## 4. OnlyOffice 插件 — Chunk 边界画框(Phase 6)

### 4.2 关键逻辑
```js
window.Asc.plugin.event.register('onToolbarClick', async () => {
  const [kbId, fileId] = window.Asc.plugin.info.fileKey.split(':')
```

## 6. 保存回调 → 重分片(Phase 7)

完整链路:

```
用户在 OO 中编辑 → Ctrl+S
  ↓
OO POST /api/kb/{kbId}/files/{fileId}/onlyoffice/callback
  body: { status: 2, url: "http://oo/.../file.docx", key: "...", token: "jwt" }
  ↓
OnlyOfficeController.callback()
  ├─ OnlyOfficeJwtUtil.verifyAndParse(payload.token)
  ├─ 比对 payload.key 与当前 kb_file 的 documentKey
  ├─ status == 2 或 == 6:
  │    ├─ HTTP GET payload.url → byte[]
  │    ├─ OnlyOfficeService.onDocumentSaved(kbId, fileId, bytes)
  │    │    ├─ FileServiceImpl.replaceOriginalFile
  │    │    ├─ documentParser.parse(bytes) → 重新提取 markdown
  │    │    ├─ persistParsedMarkdown → 写 MinIO
  │    │    └─ reChunkFile(kbId, fileId, null)  → MQ 异步重跑
  │    └─ 返 { error: 0 }
  └─ 其他 status:直接返 { error: 0 }
```

**为什么用 reChunkFile**:`FileServiceImpl.java:313-381` 已实现删 Milvus / 删 graph / 删 kb_chunk / 重发 MQ 全套,直接复用。新版本走完整 ingestion pipeline,自然 OCR + 重建向量 + 重建图谱。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| OO 冷启慢(5-10s) | skeleton + 进度提示;前端 `app-loading` 状态 |
| 容器时钟漂移导致 JWT 验证失败 | docker-compose 加 NTP 同步;或容忍 ±5 分钟时钟差,token 验证加 leeway |
| document.key 冲突(last-writer-wins) | MVP 不做协作锁,仅单用户编辑;后续加乐观锁 |
| OnlyOffice Plugin API 版本兼容 | 仅在 OO 7.4+ 测试;低版本时 chunk 边界用临时 comment 降级 |
| Windows 宿主机 `host.docker.internal` | Docker Desktop 自动支持;Linux 需 `extra_hosts` 手动映射宿主机 IP |
| viewer 角色不应触发保存 | config `editorConfig.mode = 'view'` 时 OO 不发 save 回调 |
