## 后端：保存接口验证 + 按解析策略分片实现

### 现状结论
- **保存接口已存在**：POST/PUT 将 `advanced` 自由 JSON 透传存储，新字段自动持久化（无需改 DDL/Controller）
- **缺口**：读取端 `StrategyConfigResolver.applyGroup` 未映射 5 个新字段（strategy/parentMaxChunkLength/parentAggLevel/semanticThreshold/embeddingModel）→ 存了但摄入时不生效；`rule_recursive`/`semantic` 无实现；父分片聚合硬编码开启且不读 parentMaxChunkLength/parentAggLevel

---

### 1. `StrategyConfigResolver.java` — 补全新字段映射
`applyGroup` 的 ChunkConfig 分支增加：
```java
setIfPresent(group, "strategy", v -> chunk.setStrategy(String.valueOf(v)));
setIfPresent(group, "parentMaxChunkLength", v -> chunk.setParentMaxChunkLength(((Number) v).intValue()));
setIfPresent(group, "parentAggLevel", v -> chunk.setParentAggLevel(String.valueOf(v)));
setIfPresent(group, "semanticThreshold", v -> chunk.setSemanticThreshold(((Number) v).intValue()));
setIfPresent(group, "embeddingModel", v -> chunk.setEmbeddingModel(String.valueOf(v)));
```

### 2. `ChunkingService` + `ChunkingServiceImpl` — 新增 2 个分片器
```java
/** 递归字符切分（rule_recursive）：按分隔符优先级逐级降级切分 */
List<ChunkData> recursiveChunk(String text, String strategyId);
/** 语义切片（semantic）：相邻句子向量相似度低于阈值处断开 */
List<ChunkData> semanticChunk(String text, String strategyId, String kbEmbeddingModel);
```
- `recursiveChunk`：LangChain 风格——按首个分隔符 indexOf 扫描切分（保留分隔符，支持任意字符串分隔符），超长片段递归降级下一级分隔符，最后句子边界→硬切兜底；短片段贪心合并成 ≤chunkLength 的 chunk，超限落盘带 overlap 尾部延续
- `semanticChunk`：按（。！？\n）拆句 → `EmbeddingService.embed` 分批（32）向量化（模型 = 策略级 embeddingModel，空则用 KB 级）→ 相邻余弦相似度 < threshold/100 断点 + chunkLength 硬上限；embedding 异常/无模型 → warn 并回退 `ruleBasedChunk`
- `ChunkingServiceImpl` 构造器注入 `EmbeddingService`（`@RequiredArgsConstructor`，现有测试构造需同步补参）

### 3. `ParentChunkAssembler.java` — 聚合层级支持
新增重载 `assemble(chunks, fileId, maxParentLength, aggLevel)`：
- `H1/H2/H3` → 分组键 = headingPath 截断到对应层级（"A > B > C" 取前 N 段）；`auto`/null → 完整 headingPath（现状）

### 4. `StorageService` + `StorageServiceImpl` — 聚合参数化
新增重载 `storeChunks(kbId, fileId, chunks, childChunkLength, maxParentLength, parentAggLevel)`；`childChunkLength > 0` 才聚合（现状门控），`maxParentLength <= 0` 时回退 `childChunkLength * 2`

### 5. `IngestionConsumer.java` — 按策略分发（176-193 行重构）
```java
ParseStrategyConfig config = configResolver.resolve(strategyId);
String strategy = config.getChunk().getStrategy();  // 默认 rule_fixed
// 音视频：固定走时间分段（策略不适用）
// parent_child + 有节点：structuralChunk（子分片）+ 父分片聚合（childChunkLength/maxParentLength/aggLevel）
// rule_recursive：recursiveChunk(text)
// semantic：semanticChunk(text, kbEmbeddingModel)（新增 KnowledgeBaseMapper 注入查 KB 模型兜底）
// structure_aware + 有节点：structuralChunk
// 默认（rule_fixed）：保持向后兼容——有节点走 structuralChunk，否则 chunk(text)
```
关键原则：**默认策略行为与现状完全一致**，无回归风险。
