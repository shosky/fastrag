## 目标

优化知识库 API 文档 Tab 页面：接口精简（去掉知识图谱、发布管理分组；检索服务只保留「检索知识库」）；认证鉴权统一为全局 Token（后端同步改造，但**不删除任何后端接口**）。

## 一、前端：API 文档数据精简（核心）

1. **`src/data/api-docs/index.ts`** — 从 `allApiGroups` 移除 `graphGroup`、`publishGroup`（及对应 import），保留 5 个分组：认证鉴权、知识库管理、文档管理、分片管理、检索服务
2. **删除文件** `src/data/api-docs/graph.ts`、`src/data/api-docs/publish.ts`（仅被 index.ts 引用，无其他依赖）
3. **`src/data/api-docs/retrieval.ts`** — 只保留 `POST /api/retrieval/search`（检索知识库）一个接口，删除 suggest / expand-synonyms / graph-expand / logs 四个接口的文档展示（**后端接口不动**）
4. **`src/data/api-docs/auth.ts`** — 认证鉴权分组改为「平台级全局 Token」：
   - `POST /api/api-tokens`（创建，body: name/permission/expiresIn）
   - `GET /api/api-tokens`（列表，脱敏）
   - `DELETE /api/api-tokens/{tokenId}`（撤销）
   - 去掉 kbId 路径参数，文档描述改为「Token 为平台级凭证，可访问所有知识库接口」

## 二、后端：API Token 全局化（认证统一）

5. **`fastrag-iam/.../entity/SysApiToken.java`** — 删除 `kbId` 字段
6. **`fastrag-iam/.../service/ApiTokenService.java` + `impl/ApiTokenServiceImpl.java`** — `listTokens()` 无参、`createToken(operatorId, request)` 无 kbId、`revokeToken(tokenId)` 无 kbId；token 值格式由 `frag_<kbId>_<uuid>` 改为 `frag_<uuid>`
7. **`fastrag-iam/.../controller/ApiTokenController.java`** — 路由 `/api/kb/{kbId}/api-tokens` → `/api/api-tokens`，去掉 `@PathVariable kbId`，权限注解保留 `@PreAuthorize("@perm.has('kb:manage')")`
8. **`fastrag-common/.../service/ApiTokenValidator.java`** + **`fastrag-iam/.../impl/ApiTokenValidatorImpl.java`** — 接口 `validateAndGetKbId` → `validateAndGetTokenId`（返回 token id，供过滤器构造主体）
9. **`fastrag-security/.../filter/ApiTokenAuthFilter.java`** — 主体改为 `api-token:{tokenId}`，权限保持 `kb:manage`；不再从 token 推导 kbId
10. **知识库访问放行**（token 不再绑定 kb，需对 token 主体放行 ACL 检查）：
    - `fastrag-security/.../aspect/KbAuthAspect.java`
    - `fastrag-retrieval/.../impl/RetrievalServiceImpl.java` 的 `checkKbAccess()`
    - `fastrag-retrieval/.../impl/QueryEnhanceServiceImpl.java` 的 `checkKbAccess()`
    - 三处统一：`user.hasPermission("*")` 之外，若 `userId` 以 `api-token:` 开头则放行
11. **DDL**：`fastrag-bootstrap/src/main/resources/data-mysql.sql`、`schema-h2.sql` 中 `sys_api_token` 表去掉 `kb_id` 列与 `idx_api_token_kb` 索引

## 三、前端：Token 管理对接全局接口

12. **`src/api/index.ts`** — `createApiToken`/`getApiTokens`/`deleteApiToken` 改为 `/api-tokens`（去掉 kbId）；删除无后端对应的死代码 `updateApiToken`
13. **`src/views/knowledge/detail/components/ApiTokenManager.vue`** — 去掉 `kbId` prop 依赖，改为调用全局 Token 接口（组件位置不变，仍嵌在 API 文档 Tab，按用户确认）
14. **`src/views/knowledge/detail/components/ApiDocPanel.vue`** — `<ApiTokenManager>` 不再传 `kb-id`；清理 iconMap 中已移除分组的图标（可选项）

## 四、不动的东西（按用户澄清）

- ❌ 后端所有接口（RetrievalController 的 suggest/logs 等、GraphController、PublishController）**全部保留**
- ❌ 检索日志分析页面、SearchTestPanel、debug.vue、useGraphExpansion/useSynonyms composable **全部不动**
- ❌ 知识库详情页的知识图谱 Tab、发布管理 Tab 功能保留

## 五、验证

- 后端：`mvn -q compile`（fastrag-iam / fastrag-security / fastrag-common / fastrag-retrieval / fastrag-bootstrap）
- 前端：`npm run build`（或 vue-tsc 类型检查）确认无编译错误
- 手动核对 API 文档 Tab 显示 5 个分组、检索服务仅 1 个接口、认证鉴权展示全局 `/api/api-tokens`
